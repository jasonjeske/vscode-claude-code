# Local setup interview

Copy the prompt below into Claude Code on the approved work computer. Run it
without attaching real workbooks or pasting confidential data.

```text
Help me configure Claude Code for my job through a careful setup interview.
Interview me one question at a time. Do not edit files or run commands during
the interview.

The goal is to create:
1. a concise global CLAUDE.md for how I work across projects
2. a reusable project CLAUDE.md template
3. a short list of optional local skills only for workflows that truly repeat
4. a safe first-week learning plan

Interview rules:
- Never ask for company names, employee names, taxpayer or customer data,
  property addresses, parcel or account identifiers, credentials, internal URLs,
  exact file paths, or actual financial values.
- Ask about categories and procedures using invented placeholders.
- Treat all work as confidential and regulated.
- Ask what company AI policy permits before recommending integrations, plugins,
  MCP servers, network access, or cloud services.
- Do not assume authority to make tax, legal, accounting, filing, payment, or
  journal-entry decisions.
- Prefer reviewable local workflows that preserve original files and create an
  audit trail.
- Keep the final global file under 150 lines.
- Do not add generic advice Claude already knows. Capture only my real workflow,
  constraints, verification methods, and approval boundaries.

Ask about these topics, one at a time:
1. The categories of work I perform, without real company or taxpayer details.
2. The file types I receive and produce, such as XLSX, CSV, PDF, DOCX, or text.
3. The recurring workflow steps I follow.
4. The control totals, tie-outs, review checks, and exception reports I need.
5. Which sources are authoritative when records conflict.
6. Which actions always require human approval.
7. What software and command-line tools company policy permits.
8. What data may or may not be sent to the approved Claude service.
9. How much explanation I want while learning.
10. Common mistakes, naming rules, deadlines, and handoff requirements.

After the interview:
- Summarize my answers using generic placeholders.
- Identify contradictions or missing safety decisions.
- Draft the files, but show them to me before writing anything.
- Explain where each file would be stored on Windows.
- Recommend no more than three initial skills.
- For each proposed skill, explain the trigger, benefit, risk, and why normal
  prompting is not enough.
- Do not create self-modifying instructions. Instead, propose improvements after
  repeated corrections and require my approval.
```

## What stays local

The completed interview answers, customized global instructions, project
instructions, and company-specific skills should remain on the approved work
computer. Do not commit them to this public repository. Do not place them in a
personal private repository unless the employer explicitly permits that storage.
