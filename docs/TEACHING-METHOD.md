# Why this guide teaches through work

Research reviewed September 5, 2026 (UTC). Recommendation: guided apprenticeship around one real
work outcome, with a worked example when needed, feedback on an observable check, and less help on
later attempts. This is our design judgment for this kit, not a universally best teaching method.

## Sources and what they support

- Collins, Brown, and Holum describe demonstrating expert practice, supporting attempts, coaching,
  and gradually reducing support. Their cognitive-apprenticeship framework informs the sequence;
  it does not establish that an AI is a qualified senior accountant.
  [Original article, American Educator, 1991](https://www.aft.org/ae/winter1991/collins_brown_holum).
- The IES practice guide recommends spacing learning and alternating worked examples with attempts
  (moderate evidence), and retrieval through quizzes that revisit content (strong evidence). Its
  educational setting is not an enterprise Claude Code trial. We adapt retrieval as briefly naming
  the request and check before consulting a saved example, rather than adding mandatory quizzes.
  [IES practice guide, 2007](https://ies.ed.gov/ncee/wwc/PracticeGuide/1).
- CDC training standards emphasize relevant objectives, realistic practice, feedback, usable delivery,
  and follow-up support. These are design standards, not evidence for a guaranteed proficiency gain.
  [CDC Quality Training Standards, 2025](https://www.cdc.gov/training-development/php/qts/index.html).

## How that becomes a work session

| Need | Design choice in this kit |
| --- | --- |
| Get a useful result now | Pick today's small output before choosing a lesson or skill |
| Understand an unfamiliar operation | Show one compact example with an observable action and a concise rationale |
| Learn to verify | Learner traces one figure, formula, or citation while all required controls remain in place |
| Correct a misunderstanding | Compare the observed result with the source or answer key; address the specific mismatch |
| Build independence | Move from demonstration to guided work to a learner-written request and check |
| Retain the method | Retry at the next similar task and after a gap, using one changed condition |
| Fit a slower service | Combine output and brief explanation in one response; inspect evidence without an extra chat turn |

The timing of review follows work opportunities. This kit claims no optimal session length,
retention percentage, token saving, or number of days to proficiency. Images clarify relationships;
they are not a substitute for practicing the operation. Avoid assigning fixed visual/auditory
learner types or measuring progress by pages read.

## Learn the editor before relying on it

The first session assumes neither VS Code nor Claude familiarity. Install the custom plugin and
Office package once, then ask Claude to prepare the state workspace. Each editor action serves a
work result: select the saved task, inspect an actual workbook, locate its output, and check Excel.
Later sessions introduce request editing, scoped research, reporting, and reuse. The changed-case
exercise changes both property ID and output path so the learner must use current evidence.
The approved inline Markdown editor is supported without assuming its identity; built-in preview
is the fallback. Manual file installation is a separate recovery route, not the main lesson.

## Coaching boundaries

Claude should use a practical coworker style while showing sources, checks, and uncertainty. It
must not claim professional credentials or invent company procedures. Explain the observable method
and a brief rationale, not hidden internal reasoning. A human professional retains consequential
tax/accounting decisions. A learner's successful check is not independent review of the entire job.

Reuse facts already supplied. Do not interview about the whole role, demand an explanation after
every step, or delay authorized work until a quiz is answered. Give one learning check, optional
for urgent delivery, alongside all mandatory work controls. When tools or authority are missing,
identify that blocker instead of treating it as a training failure.

## Evaluate with actual work

Observe a permitted small task: can the learner select the right inputs, request the result,
check evidence, catch one changed condition, and repeat later with less help? Keep result quality,
review time, correction count, hands-on time, elapsed time, and gateway usage separate. Feedback
should change the lesson that caused confusion, rather than adding more reading by default.

This method has not been tested with the intended learner or managed Windows setup. Evidence
supports its ingredients, not this kit's effectiveness. W33 in the Windows verification ledger
tracks an initial session and a later changed-case attempt; neither has run.
