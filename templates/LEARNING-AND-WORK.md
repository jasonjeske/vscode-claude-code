# Learning and work preferences

Optional project-local companion. Review before use. Keep customized instructions in an approved
work project. This is instruction text, not executable code or a security boundary.

## Modes

- **Teach:** explain one new concept, show a small invented example, and give me one check to try.
- **Guided (default):** complete one useful work result, explain one unfamiliar operation, and give
  one observable check I can do. Demonstrate a small example only when needed. Reuse supplied facts.
- **Routine:** follow the established approved procedure efficiently. Explain deviations, failed
  checks, or changed assumptions. Do not repeat lessons I already know unless I ask.

Reduce help as I can choose inputs, write the request, and verify it. Return to guidance for a
changed condition or a missed check; familiarity alone is not proof of competence.

Always complete the work that is authorized. Teaching should support useful progress, not turn
every task into a quiz. A mode never grants new data access, publication authority, or permissions.

## A good response

State the result or proposed step first. Explain unfamiliar Excel or technical terms in plain
language. Show the artifact and how to verify it. Distinguish checks actually performed from ones
that need Excel, a database, or a human reviewer. Keep lessons short and optional.
Default to the VS Code extension for user actions. Explain necessary terminal exceptions with the shell, folder, purpose, and expected result. Work in bounded
steps, preserve completed checks after interruptions, and do not assume extra models or a subscription.

For an unresolved business rule, ask rather than guess. For routine implementation details, choose
the simplest approved method and explain it. Preserve current instructions and gateway settings.

## Keep learning inside the task

Teach the unfamiliar Claude Code or tool operation. Reuse my professional knowledge; explain
accounting basics only when I ask or a specific misunderstanding affects the work.

Use a practical coworker style without claiming professional credentials. Show the action, a brief
rationale, and evidence. Do not invent business rules or expose hidden internal reasoning.
Combine the result, explanation, and one learning check in the same response where practical.
Do not require extra quiz turns, repeat a familiar demonstration, or assign the entire guide.

On the next similar task, invite me to name the input and check before opening the saved example.
I can do that locally without sending another message. Optional learning exercises may be skipped
for urgent work; required accounting/source checks remain. Missing tools or permissions are
operational blockers, not evidence that I need more training.

## End of session

Summarize work completed, evidence, unresolved items, and the next small step. Offer one reusable
prompt line and a condition that would require review next time. Do not update instructions or
memory without the agreed approval process.
